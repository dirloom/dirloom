# Dirloom v0.4.0-a5 move detection benchmarks

Local measurements of one structural comparison with and without Move
Detection `structural-v1`: Identity Projection v1 on both in-memory
artifacts, the two-way merge, move detection, and model validation. A second
benchmark isolates the detector on pre-projected records. No filesystem scan
is involved. Times are not CI gates. The architectural argument for linear
cost is in [Move Detection structural-v1](../contracts/move-detection-structural-v1.md#complexity);
these numbers confirm it empirically and do not replace it.

## Command

```bash
go test ./internal/comparison -bench 'BenchmarkCompareMoves|BenchmarkDetectMoves' -benchtime=10x -count=5 -run '^$'
```

Each value is the median of the 5 runs. On this hybrid-core laptop, runs of
the same case varied by up to 2.5x at 1,000 and 10,000 records. At 100,000
records, the 5 runs of each case stayed within 20% of each other. The
`unchanged` rows, where both modes execute the same code, show the residual
noise of the medians (−3% to +13%).

## Scaling from 10,000 to 100,000 records

| Measure | time | allocated bytes |
| --- | ---: | ---: |
| `Compare` none, relocated-50% | ×9.7 | ×10.4 |
| `Compare` none, ambiguous | ×11.3 | ×10.1 |
| `Compare` structural-v1, relocated-50% | ×11.3 | ×9.8 |
| `Compare` structural-v1, ambiguous | ×12.3 | ×9.6 |
| detector, relocated-50% | ×12.9 | ×8.8 |
| detector, ambiguous | ×15.5 | ×8.4 |

A quadratic step would show ×100. Allocated bytes grow by ×8.4 to ×10.4,
which is linear. Time grows by ×9.7 to ×15.5. The A4 path without detection,
which is linear by construction, shows the same excess above ×10 (×13.8 in
the v0.4.0-a4 baseline). The detector is the most sensitive because its work
is random access into maps whose 100,000-record working set (about 50 MB)
exceeds the CPU's last-level cache. No step of the detector compares candidates with each
other.

## Notes

- With no `REMOVED` or no `ADDED` record, the detector returns at once: the
  `unchanged` rows cost the same in both modes.
- At 100,000 records, `structural-v1` adds 38% to 43% time and 38% to 64%
  allocated bytes to the whole comparison when there is something to pair.
- Pre-sizing the shape intern table to the record count was measured and
  rejected: distinct shapes are far fewer than records, so the detector
  allocated 14% to 26% more at 100,000 records (48.7 to 55.7 MB and 53.4 to
  67.4 MB) and ran no faster.
- No wall-clock threshold is asserted in CI.
