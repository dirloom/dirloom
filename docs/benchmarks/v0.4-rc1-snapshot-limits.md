# Dirloom v0.4.0-rc1 snapshot reader limits

These measurements fixed the snapshot reader limits of decision D6 in the
v0.4.0-rc1 plan. They are local measurements, not CI gates; LOT 6 turns them
into versioned baselines on a reference machine.

## Environment

| Field | Value |
| --- | --- |
| Date | 2026-11-06 |
| Base | `release/v0.4.0-rc1` at `c2b63cb` |
| Go version | go1.27.2 windows/amd64 |
| CPU | Intel(R) Core(TM) Ultra 9 275HX |
| Memory | 15 GiB |

## Method

`Load` reads a valid snapshot from a reader: it reads the bytes, rejects
duplicate keys, decodes the document, validates it, rebuilds the artifact and
recomputes its fingerprint. The peak is the highest live heap (`HeapAlloc`)
sampled every 2 ms above the heap before the load. It includes garbage that
the collector has not reclaimed yet, so it varies with GC timing.

The probe recorded two runs; the benchmark reproduces the table:

```bash
go test -run '^$' -bench BenchmarkLoadPeakMemory -benchtime 1x -timeout 30m ./internal/snapshot/
```

## Results

Paths of about 82 bytes per node (1000 files per directory):

| Nodes | Size | Peak heap | Peak / size | Load time |
| ---: | ---: | ---: | ---: | ---: |
| 100 000 | 7.8 MiB | 62–103 MiB | 7.9–13.1 | 0.4–0.5 s |
| 500 000 | 39 MiB | 350 MiB | 8.9 | 3.3 s |
| 1 000 000 | 78 MiB | 716–1 033 MiB | 9.1–13.2 | 7.6–8.1 s |
| 2 000 000 | 157 MiB | 1 453–2 099 MiB | 9.3–13.4 | 13.8–14.7 s |

Long names, the most expensive valid document within both limits: 2 000 000
nodes of 132 bytes, **252 MiB, peaked at 1 674 MiB** (6.6 × its size) in 21.8 s.

A document nested 3 000 000 levels deep (6 MB) is refused in 4 ms: before
these limits, the JSON decoder already refused nesting beyond 10 000 levels.

## Limits

| Limit | Value | Reason |
| --- | ---: | --- |
| Document size | 256 MiB | the candidate value; the reader never reads past it |
| Nodes, and any JSON array | 2 000 000 | keeps the peak near 1.5–2.1 GiB at typical path lengths |
| JSON nesting | 64 levels | Snapshot Schema v1 uses 4 |
| `capture.ignore` patterns | 4 096 | |
| `requiredFeatures` entries | 64 | |

A document beyond any limit is `snapshot_limit_exceeded`: `INVALID_SNAPSHOT`,
exit 3, distinct from `snapshot_read_failure`.
