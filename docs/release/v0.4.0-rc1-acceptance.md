# v0.4.0-rc1 user acceptance packs (G5)

> **Status:** prepared by LOT 9; not run. The packs run at gate G5, after the draft audit (G4), on the **official draft binaries** that the `v0.4.0-rc1` tag builds. G5 is not authorized. The [release record](v0.4.0-rc1-release-record.md) keeps their reports.

There is one pack per system: Windows, Linux and macOS. Each runs the common steps, then the steps of its system, and fills in the [report](#report). A step passes when its result is the expected one.

## Inputs from the CTO

Before G5, the CTO names, for each pack:

- who runs it;
- the machine: system and version, and architecture (`x86_64` or `arm64`). The release has an archive for both on each system; a pack tests at least one, and the report says which.

## Prerequisites

- The GitHub CLI, signed in with access to the draft release: a draft is visible to the repository's collaborators only.
- Git 2.45 or newer.
- Go 1.26.10, for the `go install` check.
- A full clone of `dirloom/dirloom`, with its tags and its whole history (`git clone https://github.com/dirloom/dirloom.git`, without `--depth`), checked out at the tag `v0.4.0-rc1`. The showcase scripts, step 5 and the `go install` check use it. Its own `dirloom` is never built: every step runs the official binary.
- No other `dirloom` first on `PATH`, or the report says which one is there. Every step below names the binary by its path, `$DL`.

## Common steps

Work in a new, empty directory. On Windows, the commands are PowerShell 7 unless a step says otherwise; on macOS, zsh or bash.

### 1. Download and verify the draft

Linux:

```bash
gh release download v0.4.0-rc1 --repo dirloom/dirloom --dir rc1
cd rc1
sha256sum -c checksums.txt
```

macOS:

```bash
gh release download v0.4.0-rc1 --repo dirloom/dirloom --dir rc1
cd rc1
shasum -a 256 -c checksums.txt
```

Windows:

```powershell
gh release download v0.4.0-rc1 --repo dirloom/dirloom --dir rc1
Set-Location rc1
Get-Content checksums.txt | ForEach-Object {
  $hash, $name = $_ -split '\s+', 2
  if ((Get-FileHash -Algorithm SHA256 $name).Hash -ne $hash) { "MISMATCH $name" } else { "OK $name" }
}
```

Expected: 13 files (6 archives, 6 `.spdx.json` SBOMs, `checksums.txt`) and 12 lines `OK`.

Then verify the attestation of the archive you test, for example on Linux `x86_64`:

```bash
gh attestation verify dirloom_Linux_x86_64.tar.gz --repo dirloom/dirloom \
  --signer-workflow dirloom/dirloom/.github/workflows/release.yml \
  --source-ref refs/tags/v0.4.0-rc1 --deny-self-hosted-runners
```

On Windows, on one line:

```powershell
gh attestation verify dirloom_Windows_x86_64.zip --repo dirloom/dirloom --signer-workflow dirloom/dirloom/.github/workflows/release.yml --source-ref refs/tags/v0.4.0-rc1 --deny-self-hosted-runners
```

Expected: verification succeeds. This proves where the archive was built, not an independent signature ([trust model](../../SECURITY.md#release-trust-model)).

### 2. Unpack and identify

Unpack the archive. Expected: `dirloom` (`dirloom.exe` on Windows), `LICENSE`, `LICENSES/`, `README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `SECURITY.md`, `THIRD_PARTY_NOTICES.md` and `docs/`.

Set `DL` to the unpacked binary: `DL="$PWD/dirloom"` in bash or zsh, `$DL = "$PWD\dirloom.exe"` in PowerShell, where every call is written `& $DL …` instead of `"$DL" …`.

| Step | Command | Expected |
| --- | --- | --- |
| 2a | `"$DL" --version` | `dirloom 0.4.0-rc1`, exit 0 |
| 2b | `"$DL" help structural` | the six commands, exit 0 |
| 2c | `"$DL" --help` | the commands `fingerprint`, `snapshot`, `verify`, `diff`, `history`, `watch`, exit 0 |

### 3. The showcase with the official binary

From the clone at `v0.4.0-rc1`, into a directory that does not exist yet:

```bash
DIRLOOM="$DL" bash examples/showcase/showcase.sh "$HOME/rc1-showcase" > showcase.txt
```

```powershell
$env:DIRLOOM = $DL
./examples/showcase/showcase.ps1 -WorkDirectory "$HOME\rc1-showcase" > showcase.txt
Remove-Item Env:DIRLOOM
```

Expected: exit 0 (no error in PowerShell). The script stops as soon as a `dirloom` command exits otherwise than documented or writes to stderr. Keep `showcase.txt` with the report: its commit ids are the same on every machine ([showcase](../showcase.md)).

### 6. `watch`, experimental

Linux and macOS:

```bash
mkdir -p ../watched && "$DL" watch --poll 1s ../watched
```

While it runs, create a directory in `../watched` from another terminal, wait two seconds, then press Ctrl+C.

Windows, following the [PowerShell rules of the watch reference](../reference/watch.md): the watch writes its own output, and its exit status is read once it has ended.

```powershell
New-Item -ItemType Directory ..\watched -Force | Out-Null
$watch = Start-Process $DL -ArgumentList 'watch --poll 1s ..\watched' -NoNewWindow -PassThru -RedirectStandardOutput watch.txt
try {
    $watch.WaitForExit()
} finally {
    $watch.WaitForExit()
    Write-Host "exit $($watch.ExitCode)"
}
```

Create a directory in `..\watched` from another terminal, wait two seconds, then press Ctrl+C.

Expected: one generation that adds the directory, then exit 0 after Ctrl+C. `watch` is experimental and outside the freeze: a difference is recorded and classified, and the CTO decides whether it blocks.

### 7. `go install`, A14 step 2

From the clone at `v0.4.0-rc1`, with Go 1.26.10. Name the files after the system, `<os>` being `windows`, `linux` or `macos`:

```bash
cd tools/goinstall
go run . check -version v0.4.0-rc1 -go "$(GOTOOLCHAIN=go1.26.10 go env GOROOT)/bin/go" \
  -out results/check-v0.4.0-rc1-<os>.md -log results/check-v0.4.0-rc1-<os>.log
```

```powershell
Set-Location tools\goinstall
$env:GOTOOLCHAIN = 'go1.26.10'
$go = Join-Path (go env GOROOT) 'bin\go.exe'
go run . check -version v0.4.0-rc1 -go $go -out results\check-v0.4.0-rc1-windows.md -log results\check-v0.4.0-rc1-windows.log
Remove-Item Env:GOTOOLCHAIN
```

Attach both files to the report. The command exits 1 as soon as `@v0.4.0-rc1` does not install in one of its two modes, the public proxy and `GOPROXY=direct`. The simulation of `tools/goinstall` predicts that `GOPROXY=direct` fails while `v0.3.3` is the latest release, and that the public proxy succeeds only while its version list omits the seven unzippable tags. The pack does not judge the result: it goes to the CTO (plan §3.5), and a failing `@latest` needs an explicit CTO arbitration.
