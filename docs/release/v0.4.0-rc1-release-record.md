## Scope

`v0.4.0-rc1` adds no feature. It turns the eight v0.4 alphas into one release: consistent exit codes and errors, bounded untrusted input, hardened scans, user documentation, a reproducible showcase, and contracts prepared for the v0.4 freeze. Structural Watch v1 and Watch Event Schema v1 stay experimental and outside the freeze.

- Baseline: `main` at `1267b9d`, after the pre-RC junction fix #70.
- Release branch: `release/v0.4.0-rc1`, created from it on 2026-11-04.
- Toolchain: Go 1.26.10, the `go.mod` toolchain of CI and of the release builds, retained for RC1 by the CTO on 2026-11-28.

## D9 fuzz campaign

Recorded in [`v0.4.0-rc1-fuzz-campaign.md`](v0.4.0-rc1-fuzz-campaign.md):

- 27 targets, two minutes each, on 2026-11-08, with Go 1.26.10 on Windows: about 2.36 billion executions;

## D8 performance and memory baselines

Recorded in [`../benchmarks/v0.4-rc1.md`](../benchmarks/v0.4-rc1.md) and accepted by the CTO on 2026-11-28:

- the reference machine (Windows 11, 24 cores, 16 GiB, Go 1.26.10), five runs per scenario, and a 20% investigation threshold that triggers a manual review, never a CI failure;
- 37 complete workflows fit an 8 GiB commit budget: 3.4 GiB at most for a valid workflow, 4.1 GiB at most for the hostile input, maxima observed and not ceilings;
- smaller budgets, `GOMEMLIMIT`, and the Windows hang after `fatal error: out of memory` under a job limit; the user guidance is [Memory and resource limits](../reference/memory.md);
- no engine code and no limit changed.

**A14, step 2.** From a clean environment, through the public proxy and with `GOPROXY=direct`, each command with a fresh module cache:

```bash
cd tools/goinstall
go run . check -version v0.4.0-rc1 -go "$(GOTOOLCHAIN=go1.26.10 go env GOROOT)/bin/go" \
  -out results/check-v0.4.0-rc1.md -log results/check-v0.4.0-rc1.log
```

It records `go list -m -versions -retracted`, the version `@latest` selects, `go mod download -json …@v0.4.0-rc1`, and both installs with the module version and the `dirloom --version` of each binary ([`tools/goinstall`](../../tools/goinstall/README.md#check-of-a-published-tag-g4g5)). The simulation of #103 expects `@v0.4.0-rc1` to install only while proxy.golang.org omits the seven unzippable tags, and `GOPROXY=direct` to fail until a zippable stable release exists. Whatever the outcome, it goes to the CTO; a failing `@latest` needs an explicit arbitration. A14 is not closed on the simulation.
