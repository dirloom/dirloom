## Scope

`v0.4.0-rc1` adds no feature. It turns the eight v0.4 alphas into one release: consistent exit codes and errors, bounded untrusted input, hardened scans, user documentation, a reproducible showcase, and contracts prepared for the v0.4 freeze. Structural Watch v1 and Watch Event Schema v1 stay experimental and outside the freeze.

- Baseline: `main` at `1267b9d`, after the pre-RC junction fix #70.
- Release branch: `release/v0.4.0-rc1`, created from it on 2026-11-04.
- Toolchain: Go 1.26.10, the `go.mod` toolchain of CI and of the release builds, retained for RC1 by the CTO on 2026-11-28.

**A14, step 2.** From a clean environment, through the public proxy and with `GOPROXY=direct`, each command with a fresh module cache:

```bash
cd tools/goinstall
go run . check -version v0.4.0-rc1 -go "$(GOTOOLCHAIN=go1.26.10 go env GOROOT)/bin/go" \
  -out results/check-v0.4.0-rc1-<os>.md -log results/check-v0.4.0-rc1-<os>.log
```

It records `go list -m -versions -retracted`, the version `@latest` selects, `go mod download -json …@v0.4.0-rc1`, and both installs with the module version and the `dirloom --version` of each binary ([`tools/goinstall`](../../tools/goinstall/README.md#check-of-a-published-tag-g4g5)). The simulation of #103 expects `@v0.4.0-rc1` to install only while proxy.golang.org omits the seven unzippable tags, and `GOPROXY=direct` to fail until a zippable stable release exists, so the command is expected to exit 1. The acceptance packs run it again on each system at G5. The check stays mandatory. An outcome that reproduces the behavior of #103 does not block G6 (CTO, 2026-11-28); another outcome goes to the CTO. Restoring `go install` is a validation condition of `v0.4.0`, not of RC1.
