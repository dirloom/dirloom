## 1. Purpose

`v0.4.0-a3` adds the first live verification primitive to Dirloom:

```bash
dirloom verify architecture.dlm.json
```

Its single primary question is:

> **Does the structure currently observed under the selected root still match this valid structural snapshot?**

A3 is intentionally narrower than A4.

A3 answers:

```text
same structural identity?
```

A4 will answer:

```text
what exactly changed?
```

The implementation MUST preserve the contracts already frozen by A1 and A2. In particular, A3 MUST NOT redefine structural identity, snapshot persistence, canonicalization, source observation, or capture semantics.

## 3. Existing architecture relevant to A3

The current architecture already contains the complete primitives needed to implement `verify` without adding parallel engines.

The dependency direction documented by the repository is effectively:

```text
cmd/dirloom
    ↓
internal/cli
    ↓
internal/app
    ├── internal/source
    │       ↓
    │   internal/artifact
    ├── internal/identity
    │       ↓
    │   internal/artifact
    └── internal/snapshot
            ├── internal/artifact
            └── internal/identity
```

A3 MUST remain inside this dependency direction.

### 3.1 `internal/tree`

Existing responsibility:

```text
filesystem traversal
deterministic tree construction
symlink observation
depth handling
directory-only handling
gitignore loading
filter-policy application
```

The existing `tree.Scanner` is the only filesystem traversal engine A3 may use.

Important existing invariant:

```text
Scanner never follows links encountered below the selected root.
```

A3 MUST NOT add another walker based on:

- `filepath.Walk`;
- `filepath.WalkDir`;
- direct recursive `os.ReadDir`;
- Git tree traversal;
- ad hoc snapshot-to-filesystem enumeration.

### 3.2 `internal/filter`

The existing filter policy already owns:

```text
output/self exclusion
default ignores
custom ignores
gitignore
hidden entries
```

`filter.Policy.OutputPath` is already used to prevent generated output from entering the observed artifact.

A3 MUST reuse that mechanism for the reference snapshot self-exclusion case described later in this document.

### 3.3 `internal/app.Inspect`

Current request:

```go
type InspectRequest struct {
    Root              string
    MaxDepth          *int
    DirectoriesOnly   bool
    IncludeHidden     bool
    IgnorePatterns    []string
    UseDefaultIgnores bool
    UseGitIgnore      bool
```

Current pipeline:

```text

    ↓
```

This is the only filesystem observation path A3 may use.

### 3.4 `internal/source`

`source.Source` already abstracts production of a canonical artifact:

```go
type Source interface {
    Kind() Kind
    Observe(ctx context.Context) (*artifact.Artifact, error)
}
```

Existing implementations:

```text

```

`source.Filesystem` calls the existing scanner callback exactly once and then adapts the observation through `source.FromTree`.

`source.FromTree`:

- does **not** walk the filesystem;
- canonicalizes the scanner result;
- produces the A1 Canonical Structural Artifact;
- validates it.

This is exactly the abstraction A3 needs.

### 3.5 `internal/artifact`

A1 already owns Canonical Structural Artifact v1.

A canonical artifact contains:


### 3.6 `internal/identity`

# 5. Frozen A3 functional contract

## 5.1 Primary command

The A3 public syntax SHALL be:

```text
dirloom verify <snapshot> [directory]
```

Examples:

```bash
dirloom verify architecture.dlm.json
dirloom verify architecture.dlm.json .
dirloom verify architecture.dlm.json ./src
dirloom verify architecture.dlm.json --root ./src
dirloom verify architecture.dlm.json --format json
```

Rules:

```text
snapshot  required positional path
directory optional positional path
directory default "."
--root    alternative to positional directory
--format  text | json
```

`--root` and the positional directory MUST be mutually exclusive.

More than two positional arguments MUST be a usage error.

A missing snapshot positional argument MUST be a usage error.

## 5.2 Flags intentionally not supported by `verify`

A3 MUST NOT expose structural override flags:

```text
--preset
--depth
--dirs-only
--hidden
--ignore
--no-default-ignore
--no-gitignore
```

A3 MUST NOT expose presentation flags:

```text
--color
--icons
--theme
--style
```

A3 MUST NOT expose:

```text
--output
--copy
```

The root-level inherited configuration-source flags:

```text
--config
--no-user-config
--no-config
```

MUST be explicitly rejected when supplied to `verify`.

They MUST NOT be silently ignored.

Reason:

```text
snapshot Capture Semantics v1
```

is the authoritative observation scope. Re-reading or overriding current config would make verification depend on a second, potentially divergent configuration interpretation.

## 5.3 No stdin snapshot source in A3

A3 SHALL accept a snapshot file path.

Special `-` / stdin snapshot loading is deferred.

This keeps:

- reference-file self-exclusion deterministic;
- errors attributable to a concrete reference path;
- the A3 surface minimal.

This does not prohibit a later additive feature.

# 6. Exact comparison semantics

## 6.1 Reference side

The reference side MUST be loaded through:

```go
snapshot.Load(...)
```

Successful load yields:

```go
snapshot.Validated
```

The reference fingerprint used by A3 is:

```go
validated.Fingerprint
```

It MUST NOT be reparsed or recomputed by A3.

The reconstructed reference artifact is already used by the shared A2 validator to prove the embedded fingerprint.

## 6.2 Live side

The live source MUST be observed using the validated snapshot Capture Semantics.

The mapping is exact:

| Capture Semantics v1 | `app.InspectRequest` |
|---|---|
| `capture.depth` | `MaxDepth` |
| `capture.dirsOnly` | `DirectoriesOnly` |
| `capture.hidden` | `IncludeHidden` |
| `capture.ignore` | `IgnorePatterns` |
| `capture.useDefaultIgnores` | `UseDefaultIgnores` |
| `capture.useGitignore` | `UseGitIgnore` |

The implementation MUST deep-copy:

- `Depth`;
- `Ignore`.

No current configuration source participates in this mapping.

The live pipeline then remains:

```text
InspectRequest
    ↓
app.NewFilesystemSource
    ↓
source.Filesystem
    ↓
app.Inspect
    ↓
existing tree.Scanner
    ↓
source.FromTree
    ↓
artifact.Artifact
    ↓
identity.Compute
```

## 6.3 Comparison point

The comparison occurs only here:

```go
expectedFingerprint == actualFingerprint
```

where both values are typed `identity.Fingerprint`.

This is the entire A3 structural comparison.

A3 MUST NOT compare:

- raw snapshot JSON;
- canonical snapshot JSON;
- snapshot bytes;
- `artifact.nodes` arrays directly;
- child arrays recursively;
- node counts;
- raw scanner trees;
- capture objects;
- directory names;
- absolute paths.

`NodeCount`, if retained internally for diagnostics/benchmarking, is metadata only and MUST NOT determine `MATCH` or `MISMATCH`.

# 7. Result taxonomy

The public A3 machine-status vocabulary SHALL be:

```text
MATCH
MISMATCH
INVALID_SNAPSHOT
UNSUPPORTED_SNAPSHOT
SNAPSHOT_READ_ERROR
OBSERVATION_ERROR
INTERNAL_ERROR
```

## 7.1 `MATCH`

Meaning:

```text
the snapshot is valid and supported
AND
the live structure was observed successfully
AND
expected Fingerprint v1 == actual Fingerprint v1
```

## 7.2 `MISMATCH`

Meaning:

```text
the snapshot is valid and supported
AND
the live structure was observed successfully
AND
expected Fingerprint v1 != actual Fingerprint v1
```

`MISMATCH` is a successful comparison outcome.

It is **not**:

- an invalid snapshot;
- an observation failure;
- an internal failure.

## 7.3 `INVALID_SNAPSHOT`

Used when Snapshot Schema v1 input is corrupt or semantically invalid under the existing A2 validator.

Includes at least existing A2 diagnostics:

```text
invalid_snapshot_json
missing_snapshot_field
invalid_snapshot_field
invalid_snapshot_artifact
snapshot_fingerprint_mismatch
```

Critical rule:

> `snapshot_fingerprint_mismatch` is always `INVALID_SNAPSHOT`, never `MISMATCH`.

## 7.4 `UNSUPPORTED_SNAPSHOT`

Used when the snapshot is structurally well-formed enough to identify an unsupported contract requirement.

Includes:

```text
unsupported_snapshot_schema
unsupported_snapshot_artifact_version
unsupported_snapshot_feature
```

This status is separate from corruption.

## 7.5 `SNAPSHOT_READ_ERROR`

Used when the reference path cannot be read operationally, for example:

```text
file missing
permission denied
I/O read failure
path resolves to unusable input
```

This is not a claim that the snapshot bytes are invalid.

## 7.6 `OBSERVATION_ERROR`

Used when the current live structure cannot be converted into a valid current Canonical Structural Artifact.

Examples:

```text
selected root missing
root is not a directory
permission failure
filesystem race during traversal
gitignore read failure
canonical path collision in the live source
unsupported live node representation
context cancellation during observation
```

A live canonicalization failure is not a structural mismatch because a trustworthy actual Fingerprint v1 was not produced.

## 7.7 `INTERNAL_ERROR`

Reserved for broken Dirloom invariants or unexpected internal failures.

Existing indicators MUST be reused:

```go
artifact.IsInternal(err)
snapshot.IsInternal(err)
```

Unexpected impossible states in the A3 orchestration also map here.

# 9. CLI process-control implementation

The current CLI executor assumes:

```text
returned error
    ↓
print "Error: ..."
    ↓
usage ? 2 : 1
```

That is insufficient because `MISMATCH` needs:

```text
non-zero process exit
without being an error diagnostic
```

The CLI layer SHALL introduce a private explicit-exit carrier, for example conceptually:

```go
type exitError struct {
    Code   int
    Err    error
    Silent bool
}
```

Exact internal naming is implementation detail.

Required behavior:

```text
RunE renders MISMATCH normally to stdout
    ↓
RunE returns explicit exit 1, Silent=true
    ↓
Execute returns 1
    ↓
stderr remains empty
```

The same mechanism may be used after rendering machine-readable failure outcomes to keep stdout valid JSON and suppress duplicate stderr text.

This explicit-exit mechanism MUST be private to the CLI and MUST NOT change A1/A2 semantic results.

# 13. Snapshot Capture Semantics are authoritative

This is a mandatory A3 invariant.

Given:

```json
"capture": {
  "depth": 3,
  "dirsOnly": false,
  "hidden": true,
  "useDefaultIgnores": true,
  "useGitignore": true,
  "ignore": ["generated", "*.tmp"]
}
```

A3 must observe the current root using exactly those semantics.

It MUST NOT ask the current configuration resolver what the effective values are.

Consequences:

- changing `.dirloom.yaml` after snapshot creation does not silently change verify scope;
- changing user config does not change verify scope;
- CLI presets do not apply;
- presentation is irrelevant;
- the snapshot remains portable between roots.

### 13.1 `.gitignore` nuance

Capture Semantics persist:

```text
useGitignore = true/false
```

They do not persist the historical contents of every `.gitignore`.

Therefore when `useGitignore=true`, A3 applies the current `.gitignore` files through the existing scanner.

If `.gitignore` content changed and that changes the observed structure, the actual fingerprint can change.

That is correct A2/A3 behavior and does not require content hashing.

### 13.2 Custom ignore rules

`capture.ignore` already stores the effective custom patterns in order.

A3 reuses that ordered list exactly.

# 14. Reference snapshot self-exclusion

A snapshot created by:

```bash
dirloom snapshot . --output architecture.dlm.json
```

inside the inspected root intentionally excludes its own output path.

Capture Semantics v1 intentionally do not persist `OutputPath`.

A3 therefore needs an operational rule to avoid a false mismatch caused only by the reference file being present during verification.

## 14.1 Rule

After the snapshot has been validated:

1. Resolve the live root.
2. Resolve the reference snapshot path.
3. Determine whether the reference file is a descendant of the live root.
4. Derive its canonical root-relative path using the existing path/canonicalization rules.
5. Inspect the **validated expected artifact**.
6. If that relative path is **not** present in the expected artifact, pass the snapshot path as `InspectRequest.OutputPath`.
7. If that relative path **is** present in the expected artifact, do not self-exclude it.

This reuses the existing `filter.Policy.OutputPath` behavior.

## 14.2 Why conditional exclusion is necessary

Always excluding the reference path would be incorrect.

A valid reference can describe a structure that legitimately contains a file at the same path, for example when the reference snapshot was created elsewhere and later copied over an already expected file path.

A3 must not erase an expected structural node merely because it is also the current reference path.

## 14.3 Scope

This helper is operational plumbing only.

It MUST NOT become:

- a general artifact comparison;
- a changed-path detector;
- a diff engine.

# 16. Edge-case contract

## 16.3 File content changed only

Example:

```text
src/main.go path unchanged

```

```text

```

## 16.4 File added

Expected:

```text
MISMATCH
```

## 16.5 File removed

Expected:

```text
MISMATCH
```

## 16.6 Rename

Expected:

```text
MISMATCH
```


```text

```

## 16.9 Symlink

Fingerprint v1 already includes:

```text
kind
target
```

Target changed:

```text
MISMATCH
```

Same target and same path:

```text
MATCH
```

The link target contents are not read.

## 16.10 Broken symlink

A broken symlink remains a normal structural node if the current scanner can observe it.

Same path/kind/target:

```text
MATCH
```

No attempt is made to follow the missing target.

## 16.11 Windows junction

A3 inherits the current A1 scanner/source classification.

It MUST NOT add an A3-specific junction classifier.

Verification compares whatever canonical node kind A1 produces on that platform.

Cross-platform claims MUST remain limited to canonically equivalent observations; A3 must not pretend a Windows junction and a POSIX symlink are equivalent unless A1 already makes them equivalent.

## 16.12 Hidden

`capture.hidden` controls the live observation.

Current config does not override it.

## 16.13 Gitignore

`capture.useGitignore` controls whether current `.gitignore` files participate.

## 16.14 Depth

`capture.depth` controls the current observation exactly.

`null` means unlimited.

## 16.15 `dirsOnly`

`capture.dirsOnly` is authoritative.

A `dirsOnly=true` snapshot MUST be verified against a directories-only live observation.

## 16.16 Different local configuration

Current config is not read for structural verify semantics.

A malformed current `.dirloom.yaml` MUST NOT prevent verification of a valid snapshot.

## 16.17 Capture semantics changed inside a valid v1 snapshot

If the document remains valid and self-verifying, A3 uses the capture values stored in that document.

A3 does not compare Capture Semantics as identity.

If a future capture capability is mandatory, the snapshot compatibility mechanism must expose it through schema/artifact versioning or `requiredFeatures`.

# 40. Security and robustness notes

A3 does not introduce execution of snapshot-provided commands.

Snapshot values are data only.

Verify MUST:

- never follow a snapshot-provided path outside the selected root as an instruction;
- never use snapshot node paths to open each corresponding file;
- never execute symlink targets;
- never deserialize arbitrary Go types;
- rely on the current snapshot decoder limits/behavior;
- return I/O failures without partial structural claims.

The live source remains bounded by the explicitly selected root and existing scanner behavior.

# 45. Frozen decisions summary

The audit proposes the following contract decisions as implementation-ready:

1. `verify` validates the reference exclusively through the existing A2 snapshot loader/validator.
2. A validated snapshot's Capture Semantics v1 are authoritative for current observation.
3. Current Dirloom project/user configuration is not re-read to redefine verification scope.
4. The live tree is scanned exactly once through the existing A1 scanner/source pipeline.
5. The live identity is computed exactly once with `identity.Compute`.
6. The structural decision is exactly `expected Fingerprint v1 == actual Fingerprint v1`.
7. `MISMATCH` is a normal comparison outcome, not a runtime error.
8. Corrupt snapshot and live mismatch are distinct.
9. Unsupported snapshot and corrupt snapshot are distinct.
10. Verify-specific exits are frozen as `0..6` according to section 8.
11. Machine mode is `--format json`, schemaVersion `1`.
12. Machine MATCH/MISMATCH always expose expected and actual fingerprints.
13. Human verify output is never colored and never initializes the presentation stack.
14. Structural override flags are not part of A3 verify.
15. Inherited config-source flags are rejected rather than ignored.
16. The reference file is conditionally self-excluded only when it is inside the live root and not structurally expected.
17. A3 emits no node-level changes.
18. A3 does not advertise `dirloom diff` until A4 exists.
19. Fingerprint v1, Snapshot Schema v1, Snapshot Artifact Projection v1 and Capture Semantics v1 remain frozen.
20. No new source kind is introduced in A3.
