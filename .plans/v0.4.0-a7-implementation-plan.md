## 1. Purpose

`v0.4.0-a6` compares two committed trees. `v0.4.0-a7` lists how the
structure evolved commit after commit, with one fingerprint and one change
summary per commit:

```bash
dirloom history
dirloom history main --limit 50 --structural-only
dirloom history HEAD --from origin/main --format json
```

```text
Structural History (first parent, 4 commits, end: root)

5e4e835e7a1b  2026-10-30T19:40:09Z  +2 -1 ~0 >1  dlm:v1:sha256:8c1f0a…
8359198a1211  2026-10-30T18:02:41Z  no structural change
0a25bfa9bf30  2026-10-29T21:11:05Z  +1 -0 ~0 >0  merge (2 parents)
2720f6475cb7  2026-10-29T20:00:00Z  +9 -0 ~0 >0  root
```

It answers "when did the structure change, and how much?" and points to
`dirloom diff git:<parent> git:<commit>` for the detail. It is the roadmap's
"History Primitives", not the Time Machine.

A7 MUST NOT modify:

- Git Tree Source v1, Diff Result Schema v3, Fingerprint v1, Identity
  Projection v1, Canonical Identity Encoding v1, Snapshot Schema v1, Capture
  Semantics v1, Verify Result Schema v1, Move Detection `structural-v1`
- the output, statuses or exit codes of any existing command: every existing
  test and golden stays green without being edited
- the hardened Git invocation (A6): no network, no index or working tree,
  no replace objects, Git ≥ 2.45

A7 MUST NOT add:

- a second scanner, a second structural model, or a Go Git library
- a persistent cache, a database, or any file written by `history`
- full-graph traversal, per-path history, Capture Semantics on history
- author, committer identity, or commit messages in any output
- Architecture Drift, analytics, temporal charts, Time Machine UI, cloud
  services (roadmap §10 A7.8)

## 2. Existing-state inspection

Verified on `main` at `db69ea2` on 2026-10-30:

- `internal/gitsource`: `Runner` (hardened exec, cached version gate),
  `Resolve` (revision → tree, commit), `Batch` (`cat-file --batch` with the
  ordered checks; `read(id, objectKind)` is package-private; kinds are
  `tree`, `.gitignore` blob and link blob), `ParseTree`, and the Git
  `tree.Backend`. There is no commit parser.
- `internal/source/git.go`: `Git.Observe` creates a runner, resolves, starts
  a batch, scans, closes, and converts with `PortableTargets`. One
  observation costs about 4 process starts plus a batch process
  (`docs/benchmarks/v0.4-a6.md`: about 220 ms fixed cost on Windows).
- `internal/comparison.Compare(ctx, a, b source.Source, opts)` observes both
  sources, projects them, merges, detects moves and validates. There is no
  entry point taking already-observed artifacts or records.
- `identity.Compute(artifact)` returns Fingerprint v1
  (`dlm:v1:sha256:<64 hex>`).
- `internal/cli` has `fingerprint`, `snapshot`, `verify`, `diff`, `theme`,
  `completion` and help topics; no `history`.
- Git facts, checked with Git 2.56.0 on 2026-10-30 in scratch repositories:
  - `cat-file --batch` on a commit prints `<oid> commit <size>\n` then
    `tree <oid>`, zero or more `parent <oid>`, `author …`, `committer …`,
    optional headers, a blank line and the message;
  - a root commit has no `parent` header; a merge has one per parent;
  - `rev-parse --verify --quiet <tag>^{commit}` peels to the commit;
    on a tree it exits 1;
  - in a `--depth 2` clone, the shallow file lists the boundary commits; the
    boundary commit object still records its parent, and `cat-file --batch`
    answers `<parent> missing`;
  - `rev-parse --git-path shallow` names that file: `.git/shallow` in a
    checkout, `../.git/shallow` from a subdirectory, `shallow` in a bare
    repository, an absolute path from a linked worktree (relative paths are
    relative to the directory Git ran in); in a full repository the named
    file does not exist;
  - `rev-parse --is-shallow-repository` only says whether such a file
    exists, not which commits are boundaries (CTO review P1);
  - raw commit objects are not rewritten by grafts or `.git/shallow`;
    `GIT_NO_REPLACE_OBJECTS=1` keeps replace refs out (A6).
- Lessons kept from A5–A6: every helper linear in input bytes; contracts
  before code; on Windows, process starts dominate small trees; a refused
  object must not hold `Close` for the grace period (fixed in A6).

## 5. Structural History v1 (normative content for LOT 1)

### 5.1 Request

- `<revision>`: default `HEAD`; rules of Git Tree Source v1 without the
  prefix; usage error before Git runs when invalid.
- `--from <revision>`: optional; same rules; must peel to a commit.
- `--limit <n>`: integer ≥ 1, default 20; otherwise usage error.
- `--structural-only`, `--no-moves`, `--format text|json`.
- Rejected, as for `diff`: Capture Semantics flags, `--config`,
  `--no-user-config`, `--no-config`, presentation flags, `--output`,
  `--copy`.

### 5.2 Resolution

1. Version gate, object format (A6).
2. `rev-parse --verify --quiet <revision>^{commit}` → `to`; failure is
   `git_revision_not_found` ("does not name a commit").
3. Same for `--from` when present.
4. `rev-parse --git-path shallow` once; read that file if it exists
   (relative paths against the directory Git ran in): at most 16 MiB, one
   full object id per line, nothing else. Absent → no boundary. Unreadable
   or malformed → `git_shallow_invalid`.

### 5.3 Walk

```text
current = to
examined = 0
loop:
  if current == from: end = from; stop
  read commit(current)            # batch, type commit, ≤ 1 MiB, strict parse
  observe tree(current)           # batch, Git backend, no Capture Semantics
  examined += 1
  if no parent: base = empty tree; emit; end = root; stop
  read commit(first parent)       # missing → current ∈ boundary list ? end = shallow (entry has no base)
                                  #                                   : git_object_unavailable
  observe tree(first parent); compare; emit
  if first parent == from: end = from; stop      # from wins over limit at the same step
  if examined == limit: end = limit; stop
  current = first parent
```

The parent's artifact becomes the next iteration's current artifact, so
every commit is observed once.

`--from` is an exclusive bound; an explicit limit that stops the walk
before `--from` is not an error; when both apply at the same step, the end
is `from` (the range is complete):

```text
A ← B ← C ← D (HEAD)

dirloom history D --from B             → D, C            end: from
dirloom history D --from B --limit 2   → D, C            end: from
dirloom history D --from B --limit 1   → D               end: limit   (not an error)
dirloom history D --from D             → (no entries)    end: from
dirloom history D --from X             → error history_from_not_reached
                                         (X not met before end: root)
```

The error applies only when the walk ends at `root` or `shallow` without
meeting `--from`. A boundary commit listed in the shallow file whose first
parent object exists is walked through: the recorded parent is followed.

### 5.4 Commit object parsing

Strict, in order: `tree <id>`; zero or more `parent <id>`; any other headers
up to the blank line, of which exactly one `committer <ident> <unix> <tz>`.
Ids use the repository's object format. The timestamp is an unsigned
decimal without leading zeros (except `0`), at most 253402300799
(9999-12-31T23:59:59Z, the last second RFC 3339 can write with a 4-digit
year); the zone is `+HHMM` or `-HHMM`, hours 00–14, minutes 00–59. The
timestamp becomes `committedAt` in UTC; the zone is validated, then
dropped. Anything else, more than one `tree` or `committer`, a `parent`
after another header, or a size above 1 MiB → `git_commit_invalid`; the
parser never panics (fuzzed). Names, emails and the message are skipped,
never stored.

### 5.5 Entry and summary

- `fingerprint` = Fingerprint v1 of the Git Tree Source v1 artifact of the
  commit's tree with no Capture Semantics.
- `summary` = counts of the comparison of the base artifact (A) with the
  commit artifact (B), under `structural-v1` or `none`; `total` equals the
  sum.
- `structural` = `summary.total > 0`; invariant: `structural` ⇔ fingerprint
  differs from the base fingerprint. A violation is `INTERNAL_ERROR`.
- Base: first parent; the empty tree for a root commit; none at a
  `shallow` end (`structural` and `summary` absent: unknown, never `false`).
- `--structural-only` keeps only entries with `structural: true`; entries
  with `structural: false` or without a base are hidden; `range` (including
  `end: shallow`) is unchanged.

### 5.6 Diagnostics

All Git Tree Source v1 codes apply. New codes, all `OBSERVATION_ERROR`
(exit 5):

| Code | When |
| --- | --- |
| `git_commit_invalid` | malformed commit object (headers, ids, timestamp, zone), or above 1 MiB |
| `git_shallow_invalid` | the shallow boundary list cannot be read, is above 16 MiB, or holds a line that is not a full object id |
| `history_from_not_reached` | the walk ended at `root` or `shallow` without meeting `--from` |

## 6. Internal architecture changes

```text
cli history ─► app.History ─► internal/history (walk, entries, summaries)
                                   │
                   ┌───────────────┼──────────────────────────┐
                   ▼               ▼                          ▼
     gitsource.Session    source.Git (observe tree id    comparison.CompareArtifacts
     (runner, one batch,   through the session)           identity.Compute
      ReadCommit)
```

- `internal/gitsource`: `Session` (runner, object format, one `Batch`,
  `Close`), `ReadCommit(id) (Commit, error)` with the strict parser,
  `ResolveCommit(revision)`, `ShallowBoundaries()` (one `--git-path
  shallow` call and one bounded read); `objectKind` for commits (1 MiB). The existing `Resolve`, batch and backend are reused unchanged.
- `internal/source`: `Git` gains an observation path from a session and a
  tree id; `Git.Observe` builds its own session as today, so `diff` is
  unchanged.
- `internal/comparison`: `CompareArtifacts(ctx, a, b artifact.Artifact,
  refA, refB SourceRef, opts)` (or a records-level equivalent) shared by
  `Compare`; `Compare` keeps its behavior and output.
- `internal/history` (new): request, walk, entry model, validator
  (summary sums, structural invariant, ordering, end reasons).
- `internal/app`: `History(ctx, HistoryRequest)` with typed usage errors.
- `internal/cli`: `history` command, text renderer, History Result Schema
  v1 encoder.

## 8. CLI changes

- New `dirloom history` (§5.1). Text output: a header with traversal,
  count and end; one line per entry (12-character commit id, `committedAt`,
  `+a -r ~c >m` or `no structural change`, `merge (n parents)`, `root`,
  `no base (shallow)`); a closing hint to run `dirloom diff` for details.
  No ANSI; `history` takes no presentation flags.
- Completion: flags and `--format`; no ref completion.
- Help: first-parent semantics, structural nature, cost, privacy, an example
  per option.

## 9. Machine output — History Result Schema v1

```json
{
  "schemaVersion": 1,
  "status": "OK",
  "metadata": {
    "historyVersion": 1,
    "traversal": "first-parent",
    "comparisonVersion": 1,
    "identityProjectionVersion": 1,
    "moveDetection": "structural-v1"
  },
  "range": { "to": "<commit>", "from": "<commit>", "limit": 20, "end": "from" },
  "entries": [
    {
      "commit": "<commit>",
      "tree": "<tree>",
      "parents": ["<commit>"],
      "committedAt": "2026-10-30T19:40:09Z",
      "fingerprint": "dlm:v1:sha256:<64 hex>",
      "nodeCount": 697,
      "structural": true,
      "summary": { "added": 2, "removed": 1, "changed": 0, "moved": 1, "total": 4 }
    }
  ]
}
```

- Field order fixed by the encoder; `entries` is `[]` when empty; `from`
  absent without `--from`; `structural` and `summary` absent at a `shallow`
  end; `--structural-only` keeps only `structural: true` entries and never
  changes `range`.
- Transactional: the walk completes and validates before anything is
  written. Any failure, at any commit, yields one failure document
  (`schemaVersion`, `status`, `diagnostic`), never `entries` from a partial
  walk.
- Statuses: `OK` (0), `OBSERVATION_ERROR` (5), `INTERNAL_ERROR` (6). Usage
  errors are exit 2 on stderr, even with `--format json`.
- Evolution policy: the Diff Result Schema v3 rules (unknown fields
  ignored; unknown codes opaque; new optional fields and codes additive; new
  statuses, end reasons, traversals or meaning changes need v2).

## 10. Error semantics

No new exit code. Git failures keep the A6 codes. A walk that cannot reach
`--from` is `history_from_not_reached`. A broken invariant (summary sum,
structural flag, ordering) is `INTERNAL_ERROR`. Cancellation stops the walk
and reaps the batch process.

## 11. Security considerations

- Same hardening as A6 for every Git call; commit objects are untrusted:
  strict parser, 1 MiB limit, ids checked against the object format.
- Bounded work: `--limit` caps examined commits; memory holds two
  artifacts and their projections.
- Privacy: identities and messages are skipped by the parser and never
  stored or emitted; `committedAt` is the only commit metadata (Q4).
- Recorded history only: replace refs, grafts and shallow rewriting are
  never applied; a shallow end is reported, never hidden, and never stands
  in for a missing or corrupt object.
- The shallow boundary list is the only file read directly: located by Git
  (worktrees and bare repositories included), size-bounded, strictly
  parsed.

## 12. Cross-platform considerations

- Same as A6: identical JSON on Linux, Windows and macOS for the same
  repository; committer time is converted to UTC.
- Windows process starts: one session per run keeps the fixed cost to at
  most eight process starts whatever `--limit` is (two `rev-parse` per
  revision, found in LOT 3: peeling the resolved id keeps `:/<text>`
  revisions intact).

Notes from LOTS 2–4:

  repository (checked for SHA-1 and SHA-256), so a root commit's base is
  observed through Git like any other tree.
- `internal/history` holds the walk, the entry model and a validator of
  every Structural History v1 invariant; every summary in its tests is
  cross-checked against the diff path (`comparison.Compare` of

| empty repository (unborn `HEAD`) | `git_revision_not_found` |
| shallow clone (`--depth 2`) | `end: shallow`, last entry without `structural` and `summary`, exit 0 |
| shallow clone and a commit whose missing parent is not a recorded boundary (`commit-tree -p <absent id>`) | `git_object_unavailable`, not `end: shallow` |
| missing parent in a non-shallow repository | `git_object_unavailable` |
| shallow list in a linked worktree, a bare repository, a subdirectory; malformed or oversized list | same boundary detection; `git_shallow_invalid` |
| `--structural-only` on a shallow end | the base-less entry hidden; `range.end: shallow` kept |
| failure at the third commit (corrupt object) | one failure document, no `entries`, exit 5 |
| crafted committer lines (zone `+1500`, `+0060`, `0000`; timestamp with a sign, a leading zero, above 253402300799) | `git_commit_invalid` |
| replace ref on a listed commit; graft file | recorded parents and trees |
| crafted commit objects (no tree, parent after author, two committers, bad timestamp, above 1 MiB) | `git_commit_invalid` |
| partial clone `blob:none` with a link | `git_object_unavailable` at the first commit that needs the blob |
| SHA-256 repository | 64-character ids |
| linked worktree, bare repository, subdirectory | same results |
| cancellation mid-walk | prompt return, batch process reaped |
| invalid revisions (`-x`, `:path`, empty), `--limit 0`, rejected flags | exit 2, Git not run |
| same repository on Linux, Windows, macOS | byte-identical JSON |

Plus property tests: for every pair of consecutive entries, the summary
equals the counts of `dirloom diff git:<parent> git:<commit>` (with and
without moves); the structural invariant; determinism; a shell exit-code
smoke (bash and PowerShell).

### LOT 8 — Benchmarks

History of 20 and 100 commits over 1k, 10k and 100k-entry trees built with
`git fast-import` (a few changed directories per commit), against 20 and 100
separate `dirloom diff` runs; `docs/benchmarks/v0.4-a7.md`, medians of 5,
same reporting rules as A6. Initial target (not a contract): 20 commits
over a 10k-entry tree within 2 s on Windows. Report separately the memory
held by the accumulated entries at `--limit` 100 and 1000. If the target is
missed, an optional optimization reuses unchanged subtrees by (path, tree
id) within one run; it must give exactly the plain walk's results, proven
by an equivalence test.

Notes from LOTS 7–8:

- Matrix coverage. LOTS 3–6 already covered most rows: linear history,
  relocation and `--no-moves`, contents-only and empty commits, roots,
  merges and octopus, `--limit` and `--from`, shallow ends and false
  boundaries, layouts, SHA-256, crafted commits and committer lines,
  replace refs and grafts, cancellation, failure without partial result,

  `--structural-only` keeping the range, a corrupt tree deep in the history

  `dirloom fingerprint` of a fresh clone, and exit codes through bash and
