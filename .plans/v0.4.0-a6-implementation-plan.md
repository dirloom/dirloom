## 1. Purpose

`v0.4.0-a5` answers "what changed or moved between a snapshot and a live
tree?". `v0.4.0-a6` lets the same engine answer it for Git trees:

```bash
dirloom diff git:main git:feature/payments
dirloom diff git:HEAD~10 git:HEAD
dirloom diff snapshot:architecture.dlm.json git:v0.4.0-a4
```

It is a structural diff, not `git diff`: two branches that differ only in
file contents are `NO_DIFFERENCES`.

A6 MUST NOT modify:

- Fingerprint v1, Identity Projection v1, Canonical Identity Encoding v1
- Snapshot Schema v1, Snapshot Artifact Projection v1, Capture Semantics v1
- Verify Result Schema v1, Move Detection `structural-v1`
- any status or exit code
- filesystem observation: every existing scanner, CLI and golden test stays
  green without being edited

A6 MUST NOT add:

- a second scanner or a second application of Capture Semantics
- a Go Git library or any new Go module dependency
- any network access: no fetch, pull, clone, or lazy object fetch
- object substitution: `refs/replace/` is never honored
  (`GIT_NO_REPLACE_OBJECTS=1`)
- index or working-tree semantics (`git:` against `live:` stays a usage error)
- submodule recursion, LFS smudging, content hashing
- Git sources in `fingerprint`, `snapshot`, or `verify`
- history traversal (A7)

## 2. Existing-state inspection

Verified on `main` at `e9894ab` on 2026-10-29:

- `internal/source`: `Source` is `Kind()` plus `Observe(ctx)`; kinds are
  `filesystem`, `memory`, `snapshot`. `Filesystem.Observe` scans through
  `internal/tree` and converts with `FromTree(root, FromTreeOptions{RootAbs})`.
- `internal/tree.Scanner` walks with `os.ReadDir`, `entry.Info()`,
  `os.Readlink`, and reads each `.gitignore` with `os.Lstat` and
  `os.ReadFile` (no size limit). Depth, dirs-only and `.gitignore` loading
  live in the scanner; default ignores, explicit patterns, `.gitignore`
  matching and hidden detection live in
  `filter.Policy.Excludes(fullPath, relativePath, fs.DirEntry, fs.FileInfo)`.
  Hidden on Windows also reads `FILE_ATTRIBUTE_HIDDEN` through `info.Sys()`;
  a nil `Sys()` falls back to the leading-dot rule.
- `source.canonicalizeTarget` converts `\` to `/` only when the OS separator
  is `\`, and rewrites absolute targets inside `RootAbs`. Applied to Git link
  targets as is, it would make one Git tree differ between platforms.
- `internal/app/diff.go`: grammar `snapshot:<path>` | `live:<directory>`,
  split on the first colon; live is observed with the opposite snapshot's
  Capture Semantics; live against live is a usage error.
- `docs/contracts/diff-result-v2.md` line 48: "`kind` is `snapshot` or
  `filesystem`", and no extension rule anywhere in the contract.
- `go.mod` has six direct dependencies and no Git library.
- Git facts, checked on 2026-10-29:
  - Git release notes: 2.44.0 does not mention `GIT_NO_LAZY_FETCH`; 2.45.0
    introduces `git --no-lazy-fetch`;
  - local Git 2.56.0 probes in scratch repositories:
    - `cat-file --batch` on a tree prints `<oid> tree <size>\n` then
      binary entries `<mode> <name>\0<raw id>` and a final `\n`;
    - `rev-parse --show-object-format` prints `sha1`;
    - `<rev>:<path>` resolves to a tree, but `<rev>:<path>^{tree}` does not
      (everything after `:` is a path), so peeling uses `cat-file -t`;
    - a symlink is a `120000` blob whose content is the target; a submodule
      is a `160000` entry;
    - on a `--filter=blob:none` clone, `cat-file --batch` with
      `-c protocol.allow=never` and `GIT_NO_LAZY_FETCH=1` prints
      `<oid> missing` and the object stays absent; with `protocol.allow=never`
      alone the fetch is attempted and refused;
    - after `git replace A B`, `A^{tree}` resolves to B's tree; with
      `GIT_NO_REPLACE_OBJECTS=1` it resolves to A's recorded tree.
- Lessons from A5 kept here: every helper and validator stays linear in
  input bytes; generators include names sorting before `.`, interleaving
  names, UTF-8, and empty targets; contracts are written before code.

## 5. Git Tree Source v1 (normative content for LOT 1)

### 5.1 Revision and repository

- Expression `git:<revision>`; `<revision>` is the text after the first
  colon. Empty, leading `-`, NUL or newline, or an index entry (leading `:`
  other than `:/`) → usage error (exit 2).
- Repository: Git's own discovery from the process working directory
  (`GIT_DIR` and `GIT_WORK_TREE` honored as Git honors them).
- Resolution, every call under §5.2:
  - `git rev-parse --verify --quiet <revision>` → object id;
  - `git cat-file -t <oid>`:
    - `commit` → record `commit = <oid>`; tree = `<oid>^{tree}`;
    - `tag` → peel to `^{commit}` (recorded) when the tag points to a
      commit, else to `^{tree}`;
    - `tree` → used directly, no `commit`;
    - anything else, or unresolved → `git_revision_not_found`.
- Object format from `git rev-parse --show-object-format` (`sha1` → 20-byte
  ids, `sha256` → 32-byte ids); ids are emitted lowercase hex.

### 5.2 Git invocation

- Executable: `git` found by `exec.LookPath`, which refuses the current
  directory. Arguments as a list, never a shell.
- Every call: `git -c protocol.allow=never <cmd> …` with environment
  `GIT_NO_LAZY_FETCH=1`, `GIT_NO_REPLACE_OBJECTS=1`,
  `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, plus the inherited
  environment.
- Commands used, and only these: `version`, `rev-parse --verify --quiet`,
  `rev-parse --show-object-format`, `cat-file -t`, `cat-file --batch`. None
  reads the index or the working tree.
- Version gate: `git version` once per process; below 2.45 or unparsable →
  `git_unavailable`, naming the installed and required versions.
- Process lifecycle: one `cat-file --batch` per observation, bound to the
  request context. On cancellation, error, or end of observation: close its
  stdin, kill it if it has not exited within a short grace period, always
  `Wait`. No goroutine or process outlives `Observe`.

### 5.3 Batch protocol and limits

- Request: one object id per line. Response checks, in order:
  1. header is `<oid> <type> <size>\n` with `<oid>` equal to the request, or
     `<oid> missing\n` → `git_object_unavailable`;
  2. `<type>` is the expected one (`tree` for directories, `blob` for
     `.gitignore` and links), else `git_tree_invalid`;
  3. `<size>` is a decimal within the limit for that object, else
     `git_tree_invalid` naming the limit;
  4. exactly `<size>` bytes then `\n` are read; EOF or a different byte →
     `git_object_unavailable` (truncated response).
- Limits: tree object 32 MiB, `.gitignore` blob 1 MiB, link blob 4096 bytes.
- Tree entries: `<mode> SP <name> NUL <raw id>`, id length from the object
  format; any malformed entry, unknown mode, or duplicate name →
  `git_tree_invalid`.

### 5.4 Mapping and names

- Mapping: §3 decision 7. A `160000` entry is an empty directory and is
  never entered.
- Names: the existing canonical validation (UTF-8, NFC, not empty, not
  `.`/`..`, no `/`, no NUL); an NFC collision between siblings is the
  existing `canonical_path_collision`.
- Link targets: blob content, valid UTF-8, NFC. No separator rewrite and no
  root-relative rewrite (`FromTreeOptions.PortableTargets`).

### 5.5 Capture Semantics on a Git tree

- `git`↔`git`: depth unlimited, files included, hidden included, no default
  ignores, no explicit patterns, no `.gitignore`.
- `git`↔`snapshot`: the snapshot's Capture Semantics v1 through the same
  scanner code as a live tree. Trees are read only for directories the
  scanner enters. `.gitignore` files are the ones in the observed tree, at
  their tree paths. Hidden is the leading-dot rule. A `.gitignore` entry
  that is a link or a submodule is ignored as a control file, as for a
  working tree.
- Equivalence: with the same Capture Semantics, `git:<rev>` and a clean,
  lossless checkout of `<rev>` yield the same artifact. Exceptions, listed
  normatively: links checked out as files (`core.symlinks=false`); absolute
  link targets pointing inside the checkout root; initialized submodules;
  names the platform cannot materialize; a `.gitignore` above 1 MiB; Windows
  hidden attributes; files present in the checkout but not committed.

### 5.6 Structural nature

A file whose contents differ between two revisions, with the same path and
kind, produces no change. The contract and the reference show
`git:main` against `git:feature` returning `NO_DIFFERENCES` for a
contents-only difference.

### 5.7 Diagnostics

| Code | When | Status / exit |
| --- | --- | --- |
| `git_unavailable` | no `git`, or version < 2.45 | `OBSERVATION_ERROR` / 5 |
| `git_repository_not_found` | not inside a repository, or Git refuses it (`safe.directory`) | `OBSERVATION_ERROR` / 5 |
| `git_revision_not_found` | revision does not resolve locally, or resolves to a blob | `OBSERVATION_ERROR` / 5 |
| `git_object_unavailable` | object missing (including partial clones), unreadable, or a truncated batch response | `OBSERVATION_ERROR` / 5 |
| `git_tree_invalid` | malformed entry, invalid name, unsupported mode, unexpected type, size above a limit, invalid link target | `OBSERVATION_ERROR` / 5 |

Codes come from exit statuses, `--quiet` behavior and batch markers, never
from parsing Git's stderr. The message may quote one sanitized stderr line.

## 6. Internal architecture changes

```text
live:<dir> ──► filesystem backend ─┐
                                   ├─► tree.Scanner (Capture Semantics) ─► source.FromTree ─► artifact
git:<rev> ──► Git backend ─────────┘
                 ▲
                 └─ internal/gitsource: runner, resolver, batch reader, tree parser
```

- `internal/tree`: a `Backend` interface over opaque locations
  (`ReadDir`, `Child`, `ReadGitIgnore`, `ReadLink`): an absolute path for the
  filesystem, an object id for Git. Entries expose name, kind and an
  `fs.FileInfo` whose `Sys()` is the OS value (filesystem) or nil (Git). The
  scanner loses its direct `os.*` calls; the filesystem backend reproduces
  them exactly.
- `internal/gitsource` (new): `Runner` (hardened exec, version gate),
  `Resolve` (§5.1), `Batch` (§5.3), `ParseTree` (§5.3), and the Git
  `tree.Backend` whose locations are tree ids, read as the scanner descends.
  `internal/gittest` builds isolated throwaway repositories for tests.
- `internal/source`: `KindGit`; `Git` source (`Revision`, `Capture`) whose
  `Observe` runs the scanner over the Git backend and calls `FromTree` with
  `PortableTargets`.
- `internal/app/diff.go`: `DiffSourceGit`; pairing rules (§5.5); typed
  errors carrying the side.
- `internal/cli`: grammar, completion, help; Diff Result Schema v3 encoder.

## 7. Data-model changes

- `source.KindGit = "git"`.
- `comparison.SourceRef`: optional `Tree` and `Commit`, set for Git sources
  only; `validate` checks lowercase hex of 40 or 64 characters, `Commit`
  implies `Tree`, and both are empty for other kinds.
- `app.DiffSourceKind`: add `DiffSourceGit`; `DiffSourceSpec.Path` holds the
  revision for Git.
- `artifact` error codes: the five `git_*` codes.

## 8. CLI changes

- `dirloom diff <source-a> <source-b>` accepts `git:<revision>` on either
  side. `git:` against `live:` (either order) → exit 2 with a hint to use a
  snapshot or a second revision.
- Completion suggests `git:` beside `snapshot:` and `live:`; no ref
  completion in v1.
- Help: committed-tree semantics, "structural, not `git diff`", two examples.
- Rejected flags unchanged.

## 9. Machine-output changes — Diff Result Schema v3

- `schemaVersion: 3`. Everything else in v2 is kept with the same meaning.
- `sources.a` / `sources.b`: `{ "kind": "git", "nodeCount": n, "tree": "<oid>", "commit": "<oid>" }`,
  field order `kind`, `nodeCount`, `tree`, `commit`; `commit` omitted for a
  tree revision; `tree` and `commit` absent for other kinds.
- Five Git diagnostic codes.
- Evolution policy section (ADR 0006). v2 gets a superseded banner.
- For `snapshot:` and `live:` sources, a v3 document equals the v2 document
  except `schemaVersion`.

## 10. Error semantics

No new status or exit code. Git failures are `OBSERVATION_ERROR` (exit 5)
with the side preserved through the existing typed errors. Grammar errors
and `git`↔`live` are usage errors (exit 2). A broken invariant in the Git
backend is `INTERNAL_ERROR` (exit 6).

## 11. Security considerations

- Git data is untrusted: strict batch protocol and tree parsing, canonical
  name validation, size limits per object type, no submodule recursion, no
  path ever joined onto the local filesystem.
- No network: `protocol.allow=never` and `GIT_NO_LAZY_FETCH=1` on every
  call; a test proves a partial clone is not fetched.
- No substitution: `GIT_NO_REPLACE_OBJECTS=1`; a test proves a replaced
  commit yields its recorded tree.
- No code execution surface: only plumbing that does not read the index or
  run hooks, fsmonitor, or filters; no shell; `exec.LookPath` refuses the
  current directory; `safe.directory` refusals surface as
  `git_repository_not_found`.
- Option injection: revisions starting with `-` are refused before Git runs.
- Resource bounds: per-object limits; trees read only when entered; memory
  linear in observed entries; no quadratic step (A5 lesson); cancellation
  stops and reaps the child process.
- Output exposes object ids only; never revision text, repository paths,
  remotes, or branch names.

## 12. Cross-platform considerations

- `git.exe` on Windows. The Git backend never touches the working tree, so
  `core.autocrlf`, `core.symlinks` and case-insensitive filesystems never
  change a Git observation; they can make a checkout differ from its tree,
  which §5.5 lists.
- Paths and targets are canonicalized without any OS-dependent rewrite, so
  `git:X` yields identical JSON on Linux, Windows and macOS (CI matrix
  golden).
- Fixtures create links and submodules with `git update-index --cacheinfo`
  and `git mktree`, which need no OS symlink privilege, so every platform
  runs the full Git matrix.

## 17. Definition of Done (gate de sortie a6)

```text
✓ GitSource uses the common pipeline (one scanner, two backends)
✓ branch / tag / commit / HEAD~n / subtree revisions
✓ main↔feature and HEAD~n↔HEAD
✓ no implicit network (partial-clone test), no object substitution (replace test)
✓ excluded subtrees never read; bounded, strict batch protocol
✓ submodules handled safely (not followed)
✓ committed-tree and structural semantics documented; equivalence proven with its listed exceptions
✓ cross-platform Git fixtures, identical goldens on Linux/Windows/macOS
✓ Diff Result Schema v3 with evolution policy; v2 frozen and replayed
✓ no new Go dependency; existing tests unchanged
✓ contracts, ADR, reference, changelog updated
```

## 18. Explicit non-goals

- Working-tree or index source (`git:` against `live:`), staged changes.
- Fetching, remotes beyond what already exists locally.
- Submodule recursion, LFS, sparse-checkout semantics, `.gitattributes`.
- Git sources in `fingerprint`, `snapshot`, `verify`; history (A7).
- Ref completion; Git older than 2.45 (only with a CI job proving the
  guarantees on that version).
- Overriding deprecated `.git/info/grafts` or shallow boundaries: they can
  change what an ancestry expression such as `HEAD~n` resolves to, never the
  tree of an explicit commit id. Documented as a limit.
