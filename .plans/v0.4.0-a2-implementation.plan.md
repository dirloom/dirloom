## 2.3 Existing single traversal

```text

    ↓

```

A1 already proves that fingerprinting observes the filesystem once.

A2 MUST preserve that property:

```text

→ one structural observation
→ one artifact
→ snapshot + embedded fingerprint from that same artifact
```

A snapshot implementation that scans once for the artifact and again for the fingerprint is rejected.

## 2.4 Fingerprint v1

Existing package:

```text

```

Released contract:

```text

```

Current pipeline:

```text

      ↓

      ↓
Canonical Identity Encoding v1 ("DLMI")
      ↓
SHA-256
```

Important facts:

- fingerprint is not based on JSON;
- presentation is excluded;
- absolute root is excluded;
- file contents are excluded;
- source kind is excluded;
- child slice order is excluded;
- `identity.Parse` already validates the canonical representation.

**A2 MUST NOT change this pipeline.**

The snapshot’s embedded fingerprint is the A1 fingerprint of its structural artifact.

Snapshot JSON bytes are **not** fingerprint input.

## 2.6 Transactional output already exists

**A2 MUST reuse this transactional writer.**

Do not build a second snapshot-specific temp/rename implementation.

For A2, an existing regular file follows the existing Dirloom output contract and may be replaced transactionally. Conflict refusal means at minimum:

- symlink destination → reject;
- directory/non-regular destination → reject;
- missing output parent → reject;

Do not invent `--force` unless the product contract is explicitly changed.

# 3. A2 objective

A2 transforms an observed structural artifact into a durable reference.

```text
Live Structure
      ↓
StructuralSource
      ↓
Canonical Structural Artifact v1
      ↓
Snapshot Builder
      ↓
Snapshot JSON v1
```

A valid snapshot must be:

- persistent;
- portable;
- deterministic when produced from the same canonical artifact and the same capture semantics;
- self-describing enough to understand the structural view that was captured;
- self-verifying against its embedded A1 fingerprint;
- reusable later by `verify` and `diff`;
- independent from the physical project root;
- independent from presentation;
- independent from current host/user/time;
- safely serializable and safely loadable.

A2 is **not** `verify` and **not** `diff`.

# 5. Target architecture

```text
Resolved structural configuration
              │
              ▼
        StructuralSource
              │
              ▼
   Canonical Structural Artifact v1
              │
        ┌─────┴───────────┐
        │                 │
        ▼                 ▼
Snapshot Artifact     Identity Projection v1
Projection v1               │
        │                    ▼
        │             Canonical Encoding v1
        │                    │
        │                    ▼
        │                  SHA-256
        │                    │
        │                    ▼
        │          dlm:v1:sha256:<digest>
        │                    │
        └──────────┬─────────┘
                   ▼
             Snapshot v1
                   │
                   ▼
          Deterministic JSON
```

Important architectural rule:

> Snapshot Artifact Projection v1 and Identity Projection v1 are two different projections of the same Canonical Artifact.

Even if their v1 fields overlap, they MUST NOT be conflated.

Why:

- Identity Projection defines what changes the fingerprint.
- Snapshot Artifact Projection defines what is persisted.
- A future artifact may gain structural metadata that belongs in snapshots but remains outside Fingerprint v1.

Therefore:

```text
snapshot JSON ≠ identity encoding
snapshot artifact DTO ≠ identity.Record contract
```

# 8. LOT 2 — Snapshot Artifact Projection v1

Do NOT JSON-tag `artifact.Artifact` and expose the internal Go shape directly.

Create explicit persistence DTOs in a dedicated package, preferably:

```text
internal/snapshot/
```

Suggested files:

```text
internal/snapshot/
├── document.go
├── artifact_v1.go
├── capture_v1.go
├── build.go
├── encode.go
├── decode.go
├── validate.go
├── errors.go
└── compatibility.go
```

Adapt to existing conventions if necessary.

## 8.1 Persisted node record

Snapshot Artifact Projection v1 stores the minimal canonical structural representation:

```text
path
kind
target (symlink/junction only)
```

`name` is derivable from canonical path.

Hierarchy is derivable from canonical parent paths.

Do not persist duplicated information merely because the in-memory artifact stores it.

The persisted artifact MUST still be reconstructable as a valid `artifact.Artifact`.

## 8.2 Node representation

Conceptually:

```go
type NodeV1 struct {
    Path   string
    Kind   string
    Target *string
}
```

Rules:

- root path `.` MUST exist exactly once;
- root MUST be `directory`;
- non-link nodes MUST NOT have `target`;
- symlink/junction nodes MUST contain `target`, including the empty string if that is the observed target;
- path MUST already be canonical;
- the loader MUST reject malformed persisted canonical paths rather than silently normalizing them.

## 8.3 Ordering

Writer order:

```text
ascending canonical UTF-8 path bytes
```

The writer MUST emit nodes deterministically.

The reader MAY accept semantically valid node arrays in a different order, but it MUST normalize the in-memory representation before reuse.

Do not make input array order part of structural meaning.

# 11. LOT 5 — Required feature mechanism and compatibility policy

A2.7 requires a compatibility policy now, not in A3.

## 11.1 Required features

Every v1 writer emits:

```json
"requiredFeatures": []
```

The field is required.

The array MUST:

- contain strings;
- contain no duplicates;
- be deterministic;
- be sorted by the canonical writer.

For the initial v1 writer it is empty.

A future snapshot may declare:

```json
"requiredFeatures": ["some-future-feature"]
```

If the reader does not implement that feature:

```text
unsupported_snapshot_feature
```

## 11.2 Unknown fields

Compatibility policy:

- unknown `schemaVersion` → reject;
- unknown `artifactVersion` → reject;
- unknown required feature → reject;
- unknown additive JSON field in an otherwise supported v1 document → accept and ignore;
- duplicate JSON object key → reject;
- extra JSON document / trailing non-whitespace token → reject.

This allows additive evolution without pretending to support unknown mandatory semantics.

## 11.3 Unknown fields vs strict JSON

“Strict JSON” for A2 means:

- syntactically valid JSON;
- exactly one JSON document;
- required known fields present;
- required field types correct;
- duplicate object keys rejected;
- no NaN/Infinity or non-JSON syntax;
- canonical path rules enforced;
- schema/artifact/features validated.

It does **not** mean `DisallowUnknownFields`, because that would conflict with the documented additive compatibility policy.

## Gate L5

```text
✓ compatibility policy documented
✓ requiredFeatures mechanism implemented
✓ duplicate feature detection
✓ unknown mandatory feature rejected
✓ unknown additive fields tolerated
✓ unknown schema/artifact versions rejected
```

# 12. LOT 6 — Deterministic Snapshot JSON encoding

Use Go structs / explicit ordered DTOs.

Do not serialize a `map[string]any` as the canonical writer.

Use standard JSON unless a concrete requirement proves it insufficient.

Recommended writer behavior:

```text
UTF-8 JSON
2-space indentation
stable field order defined by struct layout
HTML escaping disabled
final newline
```

The same:

```text

+ Capture Semantics
+ schema versions
+ requiredFeatures
```

MUST produce identical snapshot bytes regardless of:

- absolute project root;
- OS;
- terminal;
- presentation;

Writer MUST:

- sort persisted artifact nodes by canonical path;

- not mutate caller-owned artifact slices.

## 12.2 Writer failures

- writer returning an error;
- zero-byte write where applicable.

Errors MUST propagate.

# 15. LOT 9 — Self-verification

The snapshot’s embedded fingerprint MUST be recalculated from the snapshot artifact.

```text
embedded fingerprint
        │
        ▼
identity.Parse
        │
        ▼
reconstructed Canonical Artifact
        │
        ▼
identity.Compute
        │
        ▼
exact equality?
```

If no:

```text
snapshot_fingerprint_mismatch
```

This means:

```text
CORRUPT / INVALID SNAPSHOT
```

It MUST NOT mean:

```text
STRUCTURE MISMATCH
```

`STRUCTURE MISMATCH` belongs to future A3 when a valid snapshot is compared with a live structure.

## 15.1 Important integrity boundary

Changing only Capture Semantics does not change Fingerprint v1.

Therefore document explicitly:

> The embedded fingerprint self-verifies the structural artifact. It is not a cryptographic checksum of the entire snapshot JSON document.

Do not silently imply stronger tamper protection than A2 provides.

## Gate L9
