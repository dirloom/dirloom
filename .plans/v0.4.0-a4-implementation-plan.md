## 1. Purpose

`v0.4.0-a3` answered:

```text
same structural identity?
```

`v0.4.0-a4` answers:

```text
what exactly changed?
```

A4 adds `dirloom diff <source-a> <source-b>`: a structural comparison of two
sources over Identity Projection v1 records, with a frozen machine contract
(Diff Result Schema v1), a deterministic human renderer, and stable exit codes.

A4 MUST NOT modify:

- Fingerprint v1
- Identity Projection v1
- Canonical Identity Encoding v1
- Snapshot Schema v1
- Snapshot Artifact Projection v1
- Capture Semantics v1
- Verify Result Schema v1
- verify exit codes

A4 MUST NOT add:

- a second scanner
- a second fingerprint engine
- a second snapshot validator
- move or rename detection (a rename is `REMOVED` + `ADDED`)
- a Git source
- content hashing
- live↔live diff (usage failure, exit 2)
- colors, icons, themes
- output files or clipboard support

## 3. Lots

### LOT 1 — Contract and ADR first

Write `docs/contracts/diff-result-v1.md` and
`docs/adr/0004-structural-diff.md` before the engine. They freeze:

- operations: `ADDED`, `REMOVED`, `CHANGED` only; the public JSON field name
  is `operation`;
- `CHANGED` semantics anchored to Identity Projection v1 (kind or target of an
  identical canonical path);
- path-first canonical ordering of changes;
- summary invariants (`total = added + removed + changed`, exact counts);
- the source grammar: `snapshot:<path>` and `live:<directory>`, split on the
  first colon only, lowercase case-sensitive prefixes;
- exit codes 0–6, including public status `SNAPSHOT_READ_ERROR` at exit 5;
- Diff Result Schema v1 JSON: `metadata` holds only `comparisonVersion` and
  `identityProjectionVersion`; the compared inputs are top-level `sources.a`
  and `sources.b` (`kind`, `nodeCount`). `changes` is `[]` when empty, never
  null.

### LOT 2 — Shared capture helper

Refactor `inspectRequestFromCapture` and `referenceSelfExclusion` out of
`internal/app/verify.go` into a shared helper (`internal/app/capture.go`). No
behavior change for verify; all A3 tests stay byte-for-byte green.

### LOT 3 — Snapshot source adapter

Add `source.KindSnapshot` and a `source.Snapshot` adapter wrapping an
already-validated snapshot artifact. It must not parse Snapshot Schema itself.

### LOT 4 — Comparison model

Create `internal/comparison` with this model shape:

```text
StructuralDiff
├── Metadata   (only ComparisonVersion and IdentityProjectionVersion)
├── SourceA
├── SourceB
├── Summary
└── Changes
```

- `Metadata` carries `comparisonVersion` 1 and `identityProjectionVersion` 1
  only. It does not embed the compared sources. No dates, hosts, users, or
  absolute paths;
- `SourceA` and `SourceB` are `SourceRef` values (`kind`, `nodeCount`) and
  are siblings of `Metadata` on `StructuralDiff`;
- `NodeState` (`kind`, optional `target` with explicit presence);
- `Operation`, `Change` (the public JSON name of the operation is
  `operation`), `Summary`;
- a model validator: sorted changes, no duplicate paths, ADDED/REMOVED/CHANGED
  shape rules, `CHANGED` requires `before != after`, exact summary, root never
  in changes.

Internal violations become `INTERNAL_ERROR`.

### LOT 5 — Comparison engine

`comparison.Compare(ctx, a, b source.Source) (StructuralDiff, error)`:

- check `ctx`;
- non-nil sources;
- observe each source exactly once;
- call `identity.ProjectV1` once per artifact;
- two-way merge over sorted records;
- build `Summary`;
- validate invariants.

O(N+M) comparison: no nested loops, no matrix. Root `.` is never emitted. No
move detection: a rename produces `REMOVED` + `ADDED`.

### LOT 6 — Application service

`internal/app/diff.go` with `DiffSourceSpec` / `DiffRequest`:

- resolve a snapshot via open file → `snapshot.Load` → `source.Snapshot`;
- resolve `live:` only from the opposite snapshot's Capture Semantics via the
  shared capture helper and self-exclusion;
- for snapshot↔live and live↔snapshot: load the snapshot first, then build the
  live source, then `Compare` in user order;
- for snapshot↔snapshot: load A then B deterministically and report the first
  invalid side;
- live↔live is a usage failure (exit 2);
- preserve error side A/B with typed errors, never message parsing.

### LOT 7 — CLI

`internal/cli/diff.go` and `internal/cli/diff_result.go`:

- command `dirloom diff <source-a> <source-b>`;
- `--format text|json` only;
- reject all structural/config/presentation flags (`--config`,
  `--no-user-config`, `--no-config`, `--root`, `--depth`, `--dirs-only`,
  `--hidden`, `--ignore`, `--no-default-ignore`, `--no-gitignore`, `--preset`,
  `--output`, `--copy`, `--color`, `--icons`, `--theme`) with exit 2;
- exit codes: 0 `NO_DIFFERENCES`, 1 `DIFFERENCES` (not an error; stderr
  empty), 2 usage, 3 `INVALID_SNAPSHOT`, 4 `UNSUPPORTED_SNAPSHOT`, 5
  `SNAPSHOT_READ_ERROR` or `OBSERVATION_ERROR`, 6 `INTERNAL_ERROR`;
- human renderer: exact `No structural differences.\n` when empty; otherwise a
  `Structural Diff` header, `Summary: N added, N removed, N changed, N total`,
  then `ADDED`/`REMOVED`/`CHANGED` sections (empty sections omitted), entries
  sorted by canonical path, `+`/`-`/`~` prefixes, `CHANGED` shows only changed
  attributes with `<none>` for absent targets (presentation only). No ANSI;
- JSON: single document, deterministic indentation, `EscapeHTML(false)`,
  trailing newline. Success documents use `metadata` (only
  `comparisonVersion` and `identityProjectionVersion`), top-level `sources`
  (`a` and `b`), `summary`, and `changes` (`[]` never null). Each change
  names its verb `operation`. Failure documents carry `status` and
  `diagnostic` `{source: a|b, code, message}`, including
  `SNAPSHOT_READ_ERROR`;
- usage failures stay exit 2 with a stderr human diagnostic even under
  `--format json`;
- register `newDiffCommand` in root, add help/examples, completion suggesting
  the `snapshot:` and `live:` prefixes.

### LOT 8 — Test matrix

- engine unit tests: empty, same, add, remove, changed kind, changed target,
  mixed, ordering, root never emitted, subtree add/remove;
- content-only filesystem test (exit 0, `NO_DIFFERENCES`);
- move-as-add/remove test asserting no `MOVED`/`RENAMED`;
- all three source combinations plus live/live usage failure;
- capture semantics scenarios: depth, dirsOnly, hidden, default ignores,
  gitignore, custom ignore;
- config isolation with a malformed `.dirloom.yaml`;
- self-exclusion both ways;
- snapshot validation classification (3 vs 4);
- Unicode/NFC/collision;
- case sensitivity;
- symlinks: same/different target, kind flips, broken;
- Windows junctions per existing scanner behavior;
- deep paths, massive fan-out, large subtree;
- symmetry property tests (`invert(diff(A,B)) == diff(B,A)`);
- determinism property (repeated runs byte-identical text and JSON);
- targeted fuzzing: source expression parser, comparison of valid generated
  records, invariant validator — no panic, deterministic, valid summary,
  sorted changes;
- golden fixtures: human (empty, add, remove, changed, mixed, symlink target
  change) and JSON in `testdata/diff/v1/golden/` (`no-differences`,
  `differences`, `invalid-snapshot`, `unsupported-snapshot`,
  `snapshot-read-error`, `observation-error`);
- `TestDiffShellExitCodes` covering 0/1/2/3/4/5 via a real process, reaching
  Windows CI under PowerShell (exit 6 tested internally).
